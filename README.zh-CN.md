# Easy CV

[English](README.md) | [简体中文](README.zh-CN.md)

**用 AI 管理整份简历的生命周期** —— 从零散经历 → 可复用素材库 → 按岗位定制的成稿 → 投递时导出。

Easy CV 不是「聊一次就吐一份 PDF」。它把 **事实**、**说法** 和 **版本** 分开：同一段真实经历，可以按不同方向讲成不同侧重点，而不必每次投递都从空白重写人生。

---

## 适合谁

如果你：

- 项目和履历散落在笔记、聊天记录、旧 PDF 里  
- 会投多个方向（例如 AI 工程 / 后端 / 产品）  
- 希望 AI **给建议**，最终上纸的内容仍由 **你** 点头  
- 需要可重复的闭环：**收集 → 成稿 → 对准 JD → 逐块打磨 → 导出**

---

## 简历生命周期（你真正要做的事）

可以想成四层一起长大：

| 层级 | 是什么 | 谁改 |
|------|--------|------|
| **素材库** | 从真实经历抽出的结构化事实（技术栈、成果、背景） | 作为事实写入；AI 负责提取与补全 |
| **简历纸张** | 你看到、也最终投出去的文档（联系方式、经历、项目、技能…） | 随时手改；AI 只有在你点 **应用** 后才改纸张 |
| **投递策略** | 「一样事实，多种说法」——按目标岗位取景 | 你接受 AI 改写时自动沉淀 |
| **版本** | 大改之后可回滚的快照 | 自动 + 手动 |

```text
  笔记 / 聊天 / 旧简历
            │
            ▼
   ┌─────────────────┐
   │     素材库       │  ← 长期事实底座
   └────────┬────────┘
            │ 生成全文 / 喂给改写
            ▼
   ┌─────────────────┐     点选区块 + 指令
   │    简历纸张      │◄──────────────────────┐
   └────────┬────────┘                        │
            │ 粘贴 JD                          │ 应用 / 忽略
            ▼                                  │
   ┌─────────────────┐     区块 AI 建议 ───────┘
   │  JD 匹配 + 缺口  │
   └────────┬────────┘
            │
            ▼
   策略说法分支 + 版本 → 导出 MD / 文本 / PDF
```

### 1）把经历收进素材库

**你：** 在右侧 **素材 / JD** 里粘贴项目说明、工作要点或杂记，点 **提取素材**。  
也可以从左侧简历库：**提交文件 / 项目，完成初始化**，上传 `.txt` / `.md`，或用顶栏 **导入文本**。

**AI：** 把零散文字变成结构化素材（类型、一句话摘要、标签、技术栈、灵活字段）。默认倾向 **保留完整技术栈**，而不是悄悄删掉工具名。

**为什么重要：** 素材是你的 **事实底座**。后面的全文生成、区块改写、JD 匹配都会来这里「翻旧账」，避免换赛道时忘掉以前的项目。

> 建议：先大胆往素材库倒。叙事打磨放在纸张和策略分支上，而不是靠从库里删历史。

### 2）在纸张上搭建或打开一份简历

**你：**

- 用示例简历、**空白简历**，或导入已有草稿  
- 点击中间 **纸张** 上的任意区块  
- 在右侧表单直接改标题、时间、要点、技能等 —— 手改会立刻反映到草稿  

**AI：** 你不叫它时它不插手。手改与 AI 建议是分开的，避免「一不小心被整页覆写」。

界面：

- **左** — 简历库（按时间 / 关键词 / 项目管理多份草稿）  
- **中** — 纸张（导出所见即所得）  
- **右** — AI 助手（**区块编辑** / **素材 / JD**）

### 3）逐块让 AI 改写（先建议，你再决定）

**你：** 选中区块 → 输入指令，或点快捷芯片，例如：

- 按当前投递方向改写这段  
- 量化成果  
- 补上素材库里漏写的点  
- 润色但保留技术栈  
- 精简  

然后点 **基于当前内容完善**。在 **AI 修改建议** 里看 diff（红删 / 绿增）→ **应用** 或 **忽略**。

**AI：**

- 只改当前选中区块  
- 会带上本简历最近对话、**投递策略**，以及 **简历上没用好的素材**  
- **在你点应用之前，绝不覆盖纸张**

**点应用时，系统还会：**

- 自动存一份 **简历版本**（方便回滚）  
- 在投递策略下沉淀一条 **取景 / 说法分支**（「这段经历，在这个方向上可以这样讲」）

这是产品的核心习惯：**小步、可审阅的 AI 修改**，而不是一次黑盒重写整份简历。

### 4）用素材生成完整初稿（可选启动方式）

素材够用时：

1. 选择 **目标领域**（AI/ML、后端、前端、数据、产品经理…）  
2. 点 **用素材生成完整简历**

**AI** 按该领域的侧重点起草全文。  
**你** 把它当作纸上的强初稿，再逐块打磨。

> 生成全文会 **替换当前纸张内容**。若当前稿很重要，先 **存版本**。

### 5）对准真实岗位：JD 匹配 + 挖缺口

**你：** 填写 **投递方向 / 目标岗位**（建议填），粘贴 JD，点 **分析并挖掘**。

**AI 会给出：**

- 匹配分与差距说明  
- 已覆盖 / 仍缺失的关键词  
- **可能漏写的经历** —— 素材库里对得上 JD、但纸上很弱或没有的部分  
- 可选的整篇 **JD 改写稿**

**你：**

- 方向大致对，可 **应用 JD 改写稿**；或  
- 更稳妥：对照缺口，回到「选区块 → AI 改写 → 应用」  
- 需要时用 **从 JD 匹配填入**，把关键词放进导出用的 ATS 隐藏词  

缺失关键词还会轻量写回策略的 emphasis，让后续区块改写继续对准同一目标。

### 6）养出「一样事实，多种说法」（投递策略）

不要靠复制粘贴维护五份互相打架的简历。

Easy CV 按方向维护 **投递策略**：

- 底层项目与结果不变  
- AI 工程 / 后端 / 产品等方向用不同 **角度** 和 **措辞**  
- 你每次 **应用** 区块建议，都会多沉淀一种讲法  

下次投相似岗位时，AI 已经知道你成功讲过这个项目的哪种版本。

### 7）版本、会话与记忆

| 记忆 | 作用 |
|------|------|
| **会话** | 这份简历上的对话与改写建议 |
| **区块改写历史** | 每个区块 AI 曾给过的建议 |
| **简历版本** | 全文快照（手动保存；生成全文 / JD 改写 / 应用区块后也会存） |
| **策略 / 说法分支** | 按方向的措辞记忆，不是整份简历副本 |

实验翻车时，在工具面板的版本列表里 **恢复此版本**。

**重要：** 你正在改的纸张存在 **浏览器本地**（简历库）；素材、会话、版本、策略在 **后端存储**。清站点数据会丢本地草稿，服务端记忆可能还在（反之，删掉 `.materials` 则记忆没了、本地稿还在）。

### 8）准备投递时再导出

打开 **导出**：

- **Markdown** / **文本** —— 给 ATS 或继续改  
- **打印 / PDF** —— 走浏览器打印  
- 可选 **ATS 隐藏关键词**（纸面/打印几乎看不见；开启「导出时注入」才会带上）

隐藏词只放你真实具备的技能。Easy CV 不会替你编造经历，但堆砌关键词的边界仍由你自己把握。

## 一套可执行的节奏

1. **当周发生的事** 及时丢进素材库  
2. 保留一到几份主稿（可按赛道分）  
3. 每次投递：设 **目标岗位** → 贴 **JD** → 看缺口  
4. 用 AI diff 改 **2～5 个区块**，只应用你信得过的句子  
5. **存版本**，导出，投递  
6. 下一份相近 JD 直接复用策略说法，而不是从零开始

## 如何运行

### 一条命令演示（无需 API Key）

```bash
cd easy-cv
python -m venv .venv && source .venv/bin/activate
pip install -e .
cp .env.example .env
# 没有 OPENAI_API_KEY 时自动进入 mock，可完整体验界面
python main.py
```

打开 http://127.0.0.1:8002  

默认端口 `8002`（可用 `PORT` 覆盖）。顶栏显示 **Mock** 或 **AI**。

### 使用真实模型

在 `.env` 中配置 `OPENAI_API_KEY`（可选 `LLM_MODEL`，默认 `gpt-4o-mini`）。  
不要强制 `RESUME_MOCK=1`。重启后徽章变为 **AI**。

### 前端热更新（可选）

```bash
# 终端 A
cd easy-cv && RESUME_MOCK=1 python main.py

# 终端 B
cd easy-cv/frontend && npm install && npm run dev
```

http://127.0.0.1:5173（已代理到后端）

### 生产式静态构建

```bash
cd easy-cv/frontend && npm run build
cd .. && python main.py
```

## 设计原则（让生命周期不跑偏）

1. **事实 ≠ 文案** —— 素材存真；纸张只是某一时刻的叙事。  
2. **先建议，后提交** —— 区块 AI 必须经过 应用 / 忽略。  
3. **技术栈少删** —— 工具与框架是积累，不该被「润色」掉。  
4. **一次经历，多种取景** —— 用策略分支，而不是维护 N 份分叉简历文件。  
5. **最终声音是你的** —— 导出前务必通读纸张。

## 项目结构（给开发者）

```
easy-cv/
├── main.py              # 入口（API + 静态前端）
├── resume_agents/       # 编排器、Agents、记忆、领域配置
├── frontend/            # React + Vite 界面
└── static/              # 前端构建产物
```

底层能力包括：素材提取与优化、按模块/全文生成、JD 匹配与漏写经历挖掘、区块改写、会话、版本与投递策略。  
**日常管理简历生命周期只需要用界面**，不必先读 HTTP API。
